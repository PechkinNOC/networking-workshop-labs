## Рішення

**Причина:** асиметричний роутинг.

Запит клієнта приходить на `eth1`, але маршрут до 10.10.30.100 в основній таблиці - це default через
основний інтерфейс. Відповідь виходить не з `eth1`, а через `enp1s0`, і клієнт її ніколи не отримує.

Як це видно:
- `tcpdump -ni eth1` - запити приходять
- `tcpdump -ni enp1s0` - відповіді виходять не звідти
- `ip route get 10.10.30.100` - `dev enp1s0`
- `iptables -L -n -v` - чисто, firewall не винен

**Рішення - policy routing:**

```bash
ip route add 10.10.20.0/24 dev eth1 table 100
ip route add default via 10.10.20.100 dev eth1 table 100
ip rule add from 10.10.20.1 table 100
```

Трафік з адреси 10.10.20.1 тепер шукає маршрут у таблиці 100 і виходить через `eth1`.

**Persistent:** налаштувати через netplan (`routing-policy` і `routes` з `table: 100`) або systemd-networkd.

### Ще простіший варіант - і чому він працює саме тут

Замість policy routing можна обійтись одним рядком, без таблиць і правил:

```bash
ip route add 10.10.30.0/24 dev eth1
```

Без `via` ядро вважає `10.10.30.0/24` "on-link" - нібито досяжною напряму через `eth1` - і робить ARP-запит прямо в сегмент: "хто має 10.10.30.100?". У нашому стенді клієнт і сервер сидять на одному L2 (veth-пара), а Linux за замовчуванням (weak host model) відповідає на ARP для будь-якої своєї адреси незалежно від того, на якому інтерфейсі вона піднята - а `10.10.30.100` у клієнта саме на `lo`. Тому ARP резолвиться, і маршрут працює.

**Чому в реальній мережі це не спрацює:** якщо між сервером і клієнтом стоїть справжній фізичний роутер, а не наш veth-трюк, ARP на чужу підмережу просто не дійде - `dev eth1` без `via` шукає сусіда напряму в сегменті, якого там немає. Там обов'язково потрібен `via <next-hop>`: `ip route add 10.10.30.0/24 via 10.10.20.100 dev eth1`. І чим більше різних клієнтських підмереж, тим менше сенсу перелічувати статичні маршрути один за одним - тут і виграє policy routing.

❓ **Питання в чат:** «Хтось знайшов рішення без policy routing? Чому воно спрацювало саме в цьому стенді - і чому не спрацювало б у реальній мережі з окремим роутером?»
