## Сценарій A - Hands-on

Сервер має два мережеві інтерфейси: основний (`enp1s0`, вихід назовні) і `eth1` (10.10.20.1/24).
HTTP сервіс запущений на порту 8080 і слухає на всіх інтерфейсах.
Клієнт з адресою 10.10.30.100 знаходиться за роутером 10.10.20.100.

**Симптом:** клієнт не може підключитись - з'єднання зависає.

### Як влаштоване середовище

Це один сервер, на якому ти працюєш, і **емульований клієнт** - окремий network namespace `client`
(ізольована мережа всередині цієї ж машини, як контейнер).

```
  client (namespace)                       server (ця машина, ти тут)
  +-----------------------+                +---------------------------+
  | 10.10.30.100  клієнт  |                | eth1  10.10.20.1  <-------+--- HTTP :8080
  | 10.10.20.100  роутер  | ----- eth1c -- |                           |
  +-----------------------+                | enp1s0 - основний вихід   |
                                           +---------------------------+
```

**`from-client <команда>`** - це наш аліас (скрипт-обгортка): він виконує `<команда>` **від імені клієнта**,
тобто всередині namespace `client`. Це те саме, що `ip netns exec client <команда>`.

- команда **без** `from-client` виконується на сервері - так ти діагностуєш проблему;
- команда **з** `from-client` виконується на клієнті - так ти відтворюєш симптом і перевіряєш виправлення.

Приклад: `from-client ping 10.10.20.1` - клієнт пінгує сервер. Інтерфейси клієнта: `from-client ip -br a`.

---

Спробуй підключитись від імені клієнта:

```
from-client curl -v http://10.10.20.1:8080
from-client ping 10.10.20.1
```

> Середовище налаштовується автоматично (~20 секунд після старту).
