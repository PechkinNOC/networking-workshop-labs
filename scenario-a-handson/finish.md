## Рішення

**Причина:** Та сама що в demo — асиметричний роутинг.

`ss -tlnp` показував `0.0.0.0:8080` — сервіс слухає на всіх інтерфейсах, що виглядало нормально.
Але відповідь все одно йшла через eth0 — policy routing не залежить від того на якій адресі слухає сервіс.

**Рішення — те саме:**

```bash
ip rule add from 10.10.20.0/24 table 100
ip route add default via <eth1_gw> table 100
```

**Ключовий висновок:** `0.0.0.0` означає що сервіс слухає — але відповідь іде через routing table.
