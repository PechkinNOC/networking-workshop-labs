## Сценарій C - Demo

Ти адмініструєш прикордонний роутер між двома мережами (нещодавно додали ще один сегмент - тунель чи новий канал). Клієнти скаржаться: сторінка сервісу не відкривається. Моніторинг зелений - health-check (HTTP `HEAD`-запит, маленький) проходить нормально.

Проблема: `ping` до сервісу працює. Маленький запит (`curl -I`) працює. А звичайний `curl` за тим самим адресом - висить назавжди.

Довідка, якщо якісь команди незнайомі:

- `ping` - чи є мережевий звʼязок узагалі
- `curl -I` - HEAD-запит, тільки заголовки, без тіла відповіді
- `curl -v` - повний запит, показує кожен крок
- `ping -M do -s <N>` - надіслати ICMP без права на фрагментацію (`Don't Fragment`), розміром N байт - знайти, з якого розміру пакет не проходить
- `tcpdump` - які пакети реально йдуть через інтерфейс
- `iptables -L OUTPUT -n -v` - чи щось із цього хоста дропається

Відтвори проблему:

```
from-client ping -c3 10.10.50.2
from-client curl -I http://10.10.50.2:8080/
from-client curl -v -m 8 http://10.10.50.2:8080/
```

Середовище готується автоматично, десь 10 секунд після старту.
